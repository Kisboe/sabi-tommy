The mockups are a design reference, not a copy source. Still open — these are not wording, so the rule does not settle them
  • The English and Spanish mockups are two different designs. Switch the toggle above and watch the left-hand column. The Spanish 05, 06 and 07 are a later generation — a full wavy border round the whole card, an olive ground outside it, flowers, four-point sparkles, a palm tree and a Teide-and-sea vignette in 07, different photos inside the TV. The English ones are plain cream with no border. Built to the English design in both languages, because that is the one all four English mockups agree on. If the Spanish set is the newer intent, this stage needs rebuilding to it, and 01–03 probably do too. Largest open question in the project; blocks stage 4.
  • 04 · "Tom" and "Sabi" are baked into the album bitmap. They cannot be translated, restyled, or read by a screen reader, and section 04's only copy in the doc is Always and forever! A bitmap cannot be overruled by the doc — the artwork has to be re-exported without them.
  • 04 · the album artwork is behind the mockup. 04.01.cuteintro.illustrations.brideandgroom.png has Tom in a bucket hat and a different photo of Sabi; the mockup has a striped-shirt photo of Tom and a veil photo of Sabi. Built with the asset, since that is the file that exists.
  • 05 · the arrival time contradicts itself inside the doc. Section 05 says 12:00; section 10 and FAQ 3 both say 12:30. The doc cannot outrank itself, so this stays open. Built as 12:00, the value in this section. (COPY-CONFLICTS §2.1.)
  • 05 · English and Spanish disagree on the h suffix — 12:00 against 12:00 h — inside the doc, in both directions. Same open question as the timeline (§3.6).
  • 05 · the TV holds a 35-second video (05.02…photoboothvideo, 6.6 MB, 640×480, MP4 with no file extension). This build shows a still frame from it. 6.6 MB would be most of the whole page budget and the preview repo is public. Decide whether the video ships, and if so whether it autoplays muted or waits for a tap.
  • 06 and 05 · the family photographs go to a public site. The photo-booth picture, the video still, and the childhood photos inside the album are the first personal photographs in a stage*/ folder, and those folders are copied to the public GitHub Pages preview automatically. The publish guard only greps text. Decide before pushing.
  • 07 · the download button goes nowhere. The doc says 07.areyoucominguk.travelguide_en is a PDF, but the file has no extension, so no browser will open it; …_es.pdf does. Neither is in the repo yet.
  • 07 · the two languages address different people. The doc itself asks Are you travelling from the UK? in English and ¿Vienen desde la Península? in Spanish. A Spanish guest flying from Madrid and an English guest get the same travel guide under two different questions, and a guest from anywhere else is addressed by neither. (§6.2, still unconfirmed.)
  • Spanish register. Built with the doc's wording verbatim, which is ustedes in 05 and 07. The locked decision is vosotros/tú. Deliberately not touched here so the rewrite happens once, as one job (§6.1).

Two things the doc specifies that are worth a second look on screen Body type is DM Mono in 05, 06 and 07 per the doc; all three mockups are set in a rounded sans, and DM Mono is a much heavier texture at these line lengths. And the doc writes the date as 24th October 2027 — this build sets the th as a superscript to match the mockup, which is presentation rather than wording, so say if you would rather it sat on the line. How this was drawn The stripes in 04 are a CSS gradient, not the background bitmap, so they never stretch. The wavy photo frame in 06 and the underline and download button in 07 are SVG paths generated at load; they scale uniformly and cannot squash. Every icon is sized by CSS height with width auto. The TV screen is a transparent hole in the frame PNG with the still sitting behind it, so the frame is never resampled to a different aspect. Typography warning Norican, Dancing Script, Anton, DM Mono, Caveat Brush and Anonymous Pro are loaded from Google Fonts. If you are reading this offline they fall back to system faces and the page looks wrong. Judge the type only on the deployed preview.
